# Arciin v1.1.1

A maintenance and quality release on top of v1.1.0. No database migrations.

## What's new

- **Import from Link is smarter.** Type `youtube.com/watch?v=…` or
  `example.com/video` — no `https://` needed. Paste a page or a playlist and
  Arciin shows up to five videos it found there; pick the ones you want and a
  format (MP4, Best quality, MP3 or M4A) and they are imported together, three
  at a time, the rest waiting their turn.
- **Large File Request uploads are easier to follow.** The upload page shows a
  steady, honest speed and time left (it used to swing between minutes and
  hours), a single line for several files, and "Retrying from …" when the
  connection drops. Slow uploads that keep making progress are no longer cut off
  after 24 hours.
- **See files arriving.** Folders receiving File Request uploads show a small
  progress ring ("Receiving · 38%", "2 incoming", "Waiting"), then "Received";
  an open folder shows a banner. Only you see it.
- **Sign in on your own domain.** A custom domain saved in Settings → Domain
  (for example `https://app.arciin.com`) now works for sign-in and live updates,
  with two-factor authentication required for a public domain.
- **API keys table** is easier to scan: the rate limit sits under the prefix,
  the expiry under the scopes, and Rotate is a solid button beside a solid red
  Revoke.

## Security and reliability

- File Request and share-link tokens are no longer written into Arciin's logs.
- The license server and account portal now receive only the settings they use
  — the database password and other Arciin secrets no longer reach them.
- Nightly backups only reuse a complete earlier backup, and a failed or manual
  backup is never mistaken for one.
- The startup banner reports the server's real LAN address instead of a stale
  or Docker one.

## For operators — deployment checklist

### Before deploying

1. Confirm the newest **complete** nightly backup: it has `storage/`,
   `database.dump` and `MANIFEST.txt`. Take a fresh backup if it is older than a
   day, then check its `database.dump` restores (`pg_restore --list` succeeds),
   its `MANIFEST.txt` matches the backup, and `storage/` has the expected size.
2. Confirm at least 10 GB of free disk space.
3. No database migration is needed.

### Deploy

Build and restart the self-hosted app as usual (`arciin-api`, `arciin-worker`,
`arciin-web`).

**License server and account portal (#39).** PM2 keeps an app's old environment,
so reloading is not enough — recreate the two vendor apps, then save:

```bash
pm2 delete arciin-license-server arciin-account
pm2 start ecosystem.vendor.config.cjs
pm2 save
```

Then check neither process sees `DATABASE_URL` (`pm2 env <id>`) and both are
healthy (license health endpoint; account portal loads).

**Custom domain (#40).** In this order:

1. Deploy the v1.1.1 code.
2. Save `https://app.arciin.com` in **Settings → Domain** (the owner must have
   two-factor authentication on).
3. From `https://app.arciin.com`: sign in, complete MFA, confirm the dashboard
   loads (`/api/auth/me`) and live updates arrive (Socket.IO).
4. Remove the temporary `ARCIIN_EXTRA_CORS_ORIGINS=https://app.arciin.com` line
   from `.env`.
5. Restart only `arciin-api` (with `--update-env`).
6. Repeat step 3.

### After deploying

**Sanitize historical logs (#41).** v1.1.0 wrote raw File Request and share
tokens into request logs. Every token has the form `frq_…` or `shr_…` followed
by 32 characters, which is what the command matches. Once v1.1.1 is running and
verified (it no longer writes them), rewrite these files in place — keeping each file's inode, so the
running processes keep writing to it:

- `/srv/arce-projects/arciin/logs/arciin-api-out.log`
- `/srv/arce-projects/arciin/logs/arciin-web-err.log`
- `/srv/arciin-storage/arciin/logs/api.log`

```bash
for f in /srv/arce-projects/arciin/logs/arciin-api-out.log \
         /srv/arce-projects/arciin/logs/arciin-web-err.log \
         /srv/arciin-storage/arciin/logs/api.log; do
  tmp=$(mktemp) && chmod 600 "$tmp" &&
  sed -E 's#\b(frq|shr)_[A-Za-z0-9_-]{32}([^A-Za-z0-9_-]|$)#[redacted]\2#g' "$f" > "$tmp" &&
  cat "$tmp" > "$f" && rm -f "$tmp"
done
grep -cE '(frq|shr)_[A-Za-z0-9_-]{32}' /srv/arce-projects/arciin/logs/arciin-api-out.log \
  /srv/arce-projects/arciin/logs/arciin-web-err.log /srv/arciin-storage/arciin/logs/api.log   # expect 0 each
```

Existing links keep working; nothing is revoked. Cloudflared's own entries in
the system journal are outside Arciin's control and stay readable only by root
and the `adm` group.

**Backups (#38).** After the next nightly run (or a safe manual run of
`scripts/backup.sh`), confirm the new backup contains `COMPLETE` and that it was
linked against the previous complete nightly rather than copied in full.
