# Arciin v1.1.2 — Semantic Search & Library Intelligence

Find files by what they are about, clear a crowded notification inbox without
losing history, and see what your folders and disk are really made of. Two
additive database migrations; nothing is removed.

## What's new

### Find files by meaning

- **Semantic search.** Search for "birthday party" and find `IMG_0042.jpg` —
  a photo whose name says nothing, found by what it shows. Documents are found
  by what they are about, audio and video by what is said in them.
- **Hybrid, never instead.** Keyword search works exactly as before and always
  comes first: an exact file name, then names that start with or contain your
  words, then files related by meaning, marked *Matched by meaning* or
  *Related by meaning*.
- **Private.** Everything runs on your server with a local Ollama:
  `nomic-embed-text` for meaning, a small local vision model for describing
  photos. Nothing from your library is sent to any cloud service, and Ollama
  cloud models are never used.
- **You decide when it starts.** Semantic search is off after the update. Turn
  it on in **Settings → Models → Semantic search**, then press **Index
  library**. Indexing runs in the background, one file at a time, cheapest
  first — documents and titled files are searchable within minutes; photos
  that need a description come last (about a minute each on a CPU-only
  server). You can pause, resume and rebuild at any time.
- **Never in the way.** If Ollama is stopped or the index is still building,
  search shows name matches as always, with one quiet line saying so.
- **Same visibility rules.** A file found by meaning is one you could already
  see: deleted, archived, hidden, locked, other people's backups and anything
  outside the folder or library you are in stay out, exactly as for a keyword
  search.

### Notifications

- **Clear inbox**, beside *Mark all read*. It empties your notification inbox
  on every device you use. Your **Activity** history, the audit trail and
  other people's inboxes are untouched — clearing hides, it never deletes. New
  notifications appear as usual.

### Database

- **Folders, explained.** *Database → Folders* no longer shows one big number.
  It separates **current** folders from the **legacy Computer Backup** trees
  kept when that feature was removed, and from **deleted** records, with
  filters for each and the library shown on every row. Nothing is deleted.

### Storage

- **Storage audit (read-only).** *Database* now has a storage audit that
  counts where your disk is going: managed files, trash, failed uploads,
  thumbnails, partial uploads, logs, backups (hard links counted once) and
  local AI models, plus *potential* orphan candidates to review. It never
  deletes or moves anything. Operators can run the same with
  `pnpm storage:audit`.

### Account portal

- The account portal's pages work again. They had been failing because the
  portal's build was never refreshed after a framework upgrade; deploys now
  rebuild it, and it refuses to start on a mismatched build instead of
  serving errors.

## For operators — deployment checklist

### Before deploying

1. Confirm free disk space (the storage audit, `pnpm storage:audit`, shows it)
   and take a fresh complete backup; check `database.dump` restores
   (`pg_restore --list`) and the snapshot has `COMPLETE`.
2. Two additive migrations run on deploy:
   `20261001000000_local_semantic_search` (two new tables and an enum) and
   `20261002000000_notification_clear_cursor` (one nullable column). No
   database extension is required — **pgvector is not needed**.

### Deploy

- `pnpm deploy:safe` now also rebuilds the account portal
  (`pnpm deploy:account`) on hosts that run it: staged build, version check,
  swap, restart of `arciin-account` only, page smoke test, rollback on
  failure. The portal keeps its least-privilege environment.
- Semantic search is **off** after deploy; no model is installed and no
  indexing starts until the owner does it from Settings → Models.

### After deploying

- Settings → Models → Semantic search: **Enable**, then **Index library**
  when convenient. A full first index of a library with several hundred
  camera-named photos takes hours of background work; search is useful long
  before it finishes.
- Legacy Computer Backup folders are classified, not removed. Any clean-up is
  a separate, later decision.

## Not in this release

The broad UI refresh (inspectors, import panel, navigation) is planned for
